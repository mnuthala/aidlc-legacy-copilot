# Harness specification and extension plan

## Delivered starter
The repository supplies 14 sequential Copilot roles and 18 reusable domain procedures. The Python controller manages change initialization, structural story readiness, traceability, signed plan/release approvals, command execution, current-source evidence checks and bounded repair counters. Engineering documents are generated by invoking Copilot against real BRS/sample-context inputs, not by deterministic string templates alone.

## Intended lifecycle
1. Configure actual application source roots and verified build/test adapters.
2. Record baseline and copy BRS/sample design context.
3. Analyse requirements and source; generate stories with independent clarity and quality reviews.
4. Generate HLD, LLD, supporting design documents, tasks and test plan.
5. Obtain business, technical and QA signed approval of the exact plan revision.
6. Implement approved code/scripts and tests.
7. Execute current-candidate build, unit, functional, integration and regression suites.
8. Diagnose failures; repair only approved defects within budget; escalate blocked environments or changed requirements.
9. Independently review implementation/evidence, obtain release-review signatures, then use existing human merge/UrbanCode controls.

## Acceptance criteria for application onboarding
- Reproduce the existing Ant build with the actual Java8 toolchain; inventory every supplied legacy component and module-specific version.
- Verify source_roots cover all files influencing behaviour and packaging; exclude generated outputs.
- Every adapter emits fresh correctly identified JUnit XML, propagates failures and uses controlled fixtures.
- Real WAS9 integration verifies the tested deployed package matches the candidate. Record Oracle/MQ/SOAP/JNDI/EJB configuration evidence.
- One representative BRS change completes the entire supervised lifecycle without fabricated requirements or skipped tests.

## Before unattended enterprise use
- Run pinned protected controller code on a separate trusted service and isolate worker filesystem/process permissions.
- Replace mutable local run state with immutable, authenticated run evidence and durable retry/audit records.
- Integrate organisational identity, reviewer separation, key rotation/revocation, approval expiry and environment attestations.
- Add concurrency locks, cancellation, overall wall-clock budgets and deterministic recovery.
- Integrate approved GitHub/ADO backlog publishing and UrbanCode nonproduction adapters only after explicit service authorisation.
- Keep final merge and production promotion behind existing organisational approvals.

Do not replace acceptance criteria, weaken tests, expand permissions or bypass gates while extending the harness. All control-plane changes require separate review and invalidate existing plan digests.
